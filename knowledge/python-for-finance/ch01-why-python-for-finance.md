# Chapter 1 — Why Python for Finance

## Core idea
Why Python won in finance: banks are effectively technology firms, and Python
offers the right combination of productivity, ecosystem, and performance for
data-driven and AI-first finance.

## Why Python
- **Open source** with flexible licenses — low cost of entry for banks and
  individuals alike.
- **Interpreted and dynamic**: fast iteration, ideal for prototyping.
- **Multiparadigm**: object-oriented, functional, procedural — matches
  finance's mix of modeling styles.
- **Multipurpose**: from interactive analytics to production systems, from
  desktop to cloud clusters.
- **The ecosystem**: NumPy/pandas/Matplotlib/scikit-learn/TensorFlow make up
  the scientific stack that does the heavy lifting; Python glues them.
- The "Zen of Python" (PEP 20) guides style: readability, explicitness,
  "there should be one obvious way to do it."

## Technology trends driving Python in finance
- **Technology is an enabler and a barrier**: talent and tech are the real
  moats; Python lowers the talent barrier.
- **Speed, frequency, and data volumes keep rising** — from EOD to tick data,
  from kilobytes to terabytes; tools must scale.
- **Real-time analytics**: interactive notebooks (Jupyter) and streaming
  become the norm, not batch reports.
- **Data-driven finance**: decisions grounded in data.
- **AI-first finance**: machine/deep learning applied to markets — the theme
  of the book's strategy chapters.

## Productivity argument
- Python syntax reads close to pseudocode — finance domain experts can
  express models directly.
- Prototype-to-production: the same code (with modest hardening) can move
  from a notebook to a live trading process.
- "From Prototyping to Production" is the book's through-line: Jupyter for
  research, then packaging (e.g., the DX library in later chapters) for
  deployment.
